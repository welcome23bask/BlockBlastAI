# BlockBlastAI v1.1 — Adaptive Themes + Faster Highlighting (experimental)

Branch: `feature/v1.1-adaptive-themes` from the prior `feature/v1.0-fast-vision`. v0.8.2, v0.9 and v1.0 remain unchanged and available as backups.

## Issue reproduced
The user submitted a real **709×1536 brown wood-themed game screenshot** with a fully empty board and three tray pieces: red 3×3 (9 cells), green L tetromino (4 cells), and purple L tetromino (4 cells). The old scanner assumes navy-blue board pixels and can confuse the wood background with orange/red pieces.

## Changes
- Keep the known blue/navy detector as first choice. When it cannot recognize a valid board/tray, a separate adaptive detector searches for the four high-contrast boundaries of a square board near the 44%-height anchor and checks for a repeated 8×8 cell grid.
- Estimate **board and tray background RGB separately, from each new frame**, instead of treating warm wood as a colored piece. Reject non-tile background and uncertain geometry.
- Confirm inverted ReplayKit frames with an orientation-aware test.
- Lower the auto-scan timer from 0.38 to **0.24 seconds**; reduce capture-hidden warmup from 60 to **40 milliseconds**. The scan timer is not an end-to-end latency guarantee, and ReplayKit may deliver frames slower.
- Remove false restarts triggered merely by identical images on static or completely empty boards. The fresh ReplayKit frame counter and watchdog still reject missing frames.
- Keep asynchronous solver, exact expected-move first-frame fast path, secondary confirmation for ordinary scans, manual fallback and movable/resizable overlay.

## Validation
Local C detector tests against the uploaded screenshot at 709×1536 found board=0 and pieces=9,4,4, including correct L rotations, with both upright and reversed-frame input. A separately generated brown-theme fixture with three occupied squares also passed at 430×932.

GitHub CI tests must pass: old blue-theme vision cases, wood-theme fixture, orientation, solver legality, fast transition, browser simulator and full iOS ARM64 compile. This version has **not** been validated in the user's signed Block Blast IPA. Keep a working backup and use a non-critical save.

## Known limitations
No promise of zero-millisecond response, arbitrary unsupported theme recognition, automatic taps/drags, or predicting unseen future piece generation. UI may briefly hide during capture so its own highlights don't contaminate the screenshot. If the new detector is uncertain, the correct behavior is to show **no** highlight rather than an unsafe placement.
