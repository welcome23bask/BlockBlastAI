# BlockBlastAI v1.6 — SMART SURVIVAL + optional YOLOv8n/Core ML vision

## User's stated priorities (2026-11-14)

**Keep the combo going. A single-line clear is enough.** Do not abandon a streak just because there is a larger 3/5-line clear available later, provided the small clear still leaves a safely playable board. The 100M-score target is aspirational and cannot be guaranteed.

## SMART SURVIVAL solver

- Three selectable modes in the existing resizable iPhone panel: MAX LINES, KEEP COMBO, **SMART SURVIVAL** (new default).
- Keeps our legal three-piece search, ReplayKit capture, pink/blue/wood/other color classifier, original blinking guides and verified combo tracker.
- SMART SURVIVAL enumerates legal orderings of all currently visible pieces within the bounded 180,000-node search budget. When an active combo is confirmed, it favors a **combo-preserving** complete-tray placement path, even if it clears only one line.
- The combo choice is accepted only if its post-tray survival score is within a bounded tolerance of the most spacious available path. It rejects an active-combo alternative if it would lose a previously available 3x3 or five-long landing space on a crowded board.
- Survival scoring includes remaining empty cells, accessible 3x3/3x2/2x3 and five-long slots, rough jagged occupied runs, isolated free islands, and fragmented regions. These are heuristics, not probabilities derived from the actual game's unknown piece distribution.
- The interface labels a budget-limited search as approximate; it never treats guessed future pieces as known.
- User's actual screenshot regression: MAX LINES clears five lines on move 3, while SMART SURVIVAL chooses an immediate clear preserving a verified near-expiration streak (source tests: `tests/test_smart_survival.c`, `tests/test_dual_strategy.c`).
- Unit-test passing does not prove average survival or combo rate across long live runs. This branch remains experimental until paired independent long-game holdouts and real iPhone gameplay are reviewed.

## YOLOv8n vision — real iPhone integration, not yet a trained model

- An OPTIONAL on-device Core ML adapter is implemented in `src/BLYOLOVision.m` with Vision's `VNCoreMLRequest`.
- When a custom **trained** and compiled `BlockBlastYOLOv8n.mlmodelc` directory exists in the app bundle or next to `BlockBlastAI.dylib`, it can be loaded and used **after** the established native scanner fails.
- Expected object detection classes: `board`, `occupied_cell`, `tray_cell`. The adapter validates board position/size near the center of the portrait screen; snaps occupied-cell detection centers to 8x8 grid; clusters tray cells into three groups; and rejects duplicates, inconsistent offsets, disconnected pieces and low-confidence detections. Invalid results never replace safe native scanning.
- **The repository DOES NOT include custom-trained YOLO weights.** Generic pretrained `yolov8n.pt` detects COCO objects, not Block Blast squares. Without labeled data and a working model, the app uses the existing native color/geometry detector, so installing just the .dylib does **NOT** activate YOLO detection.
- `training/train_yolov8n.py` validates annotated training and validation data, trains YOLOv8n, reports held-out mAP and exports a Core ML `.mlpackage` with NMS. On macOS, `xcrun coremlcompiler compile training/exports/BlockBlastYOLOv8n.mlpackage training/exports/` creates the `.mlmodelc` package for inclusion alongside the library.
- For reliable performance, manually validate **full board reconstruction and tray cell exactness**, not just YOLO bounding-box mAP, across held-out screenshots from different skins, device sizes, captures and game sessions.
- This implementation uses the documented Ultralytics YOLOv8/CoreML approach but does **not** copy Block Blast Solverss's privately trained model, weights, inference API or server.
- Model processing remains on-device; no images, board history or scores are transmitted. Observe Ultralytics' AGPL-3.0 / Enterprise and game distribution rules before publishing.

## Training from actual screenshots

1. Create screenshots with full 8x8 board and visible tray, including pink/blue/wood/neon skins, sparse and crowded stages, and start/end transitions. Obtain rights/permission for all recordings.
2. In CVAT/Roboflow/Label Studio, label one `board` box, each visible occupied `occupied_cell`, and each visible `tray_cell`. Save the YOLO detection TXT labels under `training/dataset/images/{train,val}` and `training/dataset/labels/{train,val}`. Use the exact class IDs in `training/dataset.yaml.example`. Hold out **entire game sessions and skins** for validation; don't split adjacent frames randomly.
3. `pip install ultralytics`, then `python training/train_yolov8n.py --dataset training/dataset --epochs 120`. The script requires at least 100 labeled training and 25 validation screenshots and sufficient boxes of every class; this is a minimal sanity gate, not sufficient evidence of production accuracy.
4. Exported `training/exports/BlockBlastYOLOv8n.mlpackage` must be compiled on macOS: `xcrun coremlcompiler compile training/exports/BlockBlastYOLOv8n.mlpackage training/exports`.
5. Place `training/exports/BlockBlastYOLOv8n.mlmodelc` alongside the signed `BlockBlastAI.dylib` or in the app's main bundle, then restart the host game. Adding a model to an already signed IPA requires rebuilding/resigning it.
6. Check detection confidence and exact 8x8/tray cells against screenshots not used for training, then verify several full live games before making claims about vision accuracy.
7. If YOLO produces non-`VNRecognizedObjectObservation` outputs after Core ML export, the adapter safely declines them and the export/inference contract must be adjusted. This integration has not been live-tested with a custom YOLO weights file.

## Validation and ethics

- The 3rd mode is original source code and does not connect to blockblastsolverss.com.
- An apparently correct one-line clear may harm future survival; the safety score is intended to handle that tradeoff but is not an optimality proof.
- No game state tampering, score multiplier, hidden-piece access or automatic placement is performed here.
- iPhone CI compilation and synthetic move tests verify only the build and expected model/board behavior; it does not prove a 100M score, the site's algorithm, or actual on-device YOLO effectiveness.
