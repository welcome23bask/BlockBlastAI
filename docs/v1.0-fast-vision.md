# BlockBlastAI v1.0 Fast Vision — experimental branch

Source branch: `feature/v1.0-fast-vision`. This work builds on `feature/v0.9-smart-ai` and does **not** replace the user's confirmed working v0.8.2 installation.

## Improvements in this prototype
- **Quicker refresh cadence:** 0.38-second scan timer instead of 1.2 seconds; capture overlay-hide warmup reduced from 0.20 seconds to 0.06 seconds.
- **More responsive highlights:** ordinary new board+tray states require two matching **fresh, independently captured** frames instead of three. Mid-animation/partial transitions still require three.
- **Expected-move fast path:** after a displayed recommendation, an observation can trigger immediately **only** when the recognized board equals the predicted board after placing the first recommended piece, that piece disappears from the tray, and all remaining pieces match. The pure C verifier has independent positive and negative tests.
- **Nonblocking decisions:** the 192-state v0.9 planner runs on a background priority queue. Every calculation is generation-tagged so obsolete results cannot repaint highlights after a scan changes, an error occurs, or the overlay is paused.
- **Faster recognition:** avoid an unnecessary full-size UIKit image redraw for already-upright ReplayKit frames; retain orientation fallback.
- **Self-aligning highlights:** auto-calibration remains active and small jitter is damped. Large unexpected geometry changes still clear highlights.
- **Mistake prevention and recovery:** existing capture watchdog, frozen-frame detection, false-orientation rejection, auto-rescanning, movable/resizable controls, and manual fallbacks remain in place.

## Not promised
"Instant" is an engineering target, not a zero-millisecond or guaranteed latency claim. The effective delay still depends on ReplayKit frame delivery, iPhone speed, transition animations, and confidence checks. Reducing the confirmation threshold can increase false detections; never trust a highlight until real device validation.

The code uses screen images only; it cannot press or drag game pieces, change game scores or memory, predict unseen future pieces, or bypass iOS capture permissions. There is no machine-learning model or remote AI service.

## Validation checklist
1. The GitHub macOS workflow must pass pure C solver tests, 300 randomized path tests, independent expected-move transition tests, vision/orientation tests, simulator tests, 2,000 matched benchmark games, 1,000 holdout games, and ARM64 iOS dylib compilation.
2. Download the `BlockBlastAI-v10-fast-iOS-arm64` artifact from a **successful** v1.0 run.
3. Keep v0.8.2 and v0.9 backups. Test v1.0 in a separate compatible signed IPA using KSign, injecting only one dylib.
4. With the overlay closed and a clear board: verify top-left/bottom-right alignment, all 8x8 cells, all remaining tray shapes, and accurate in-board highlight geometry.
5. Place the highlighted first piece. Verify the next suggested placement updates, including when a row or column is cleared. Also test unexpected placement, opening/closing the panel, orientation changes, animation, long idle screens, and ReplayKit interruptions.
6. Record observed latency from visible piece change to correct highlight on the actual iPhone; do not call this device-verified until it survives a 10+ minute gameplay session.

Known limitation: the simulator's tray generator is not the real game's generator; seeded test wins do not prove actual high-score improvement. Real screen capture and real game animations must be tested on device.
