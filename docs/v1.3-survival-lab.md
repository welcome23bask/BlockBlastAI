# BlockBlastAI v1.3 Survival Lab — NOT RELEASED / NOT 100M-VALIDATED

This experimental branch was forked from the user's last preferred **v1.1 BLINK**. The capture path, visual color detection, movable/resizable overlay and flashing highlights are intentionally unchanged; only the move-decision engine and developer benchmarks have changed.

## Goal
Increase real-world **survival duration** over many three-piece trays, while maintaining accurate fast highlighting. **100 million points is an aspirational user target, not a guarantee or a demonstrated threshold.** Upcoming pieces are hidden, the iOS game's generator/scoring/updates aren't reproduced here, and scores from external screenshots may use different bonuses or multipliers.

## Implemented experimental work
- Frozen `benchmark/v11_blink_solver.c` provides a byte-for-byte v1.1 baseline comparison.
- 256-state beam search (vs v1.1's 192).
- Board occupancy/fragmentation penalties and 14 representative unseen-shape accessibility checks (3x3, 1x5/5x1, rectangles, L/Z variants). These are hypothetical risk tests, **not** a reverse-engineered prediction of the game's hidden RNG.
- Shape forecast is evaluated only on beam finalists, not for every enumerated placement, to preserve responsiveness.
- Optional future line-clear readiness heuristic; compile-time coefficient permits independent A/B experiments (default 0 until proven).
- Bounded exhaustive rescue fallback when the beam cannot place all remaining visible pieces, avoiding avoidable immediate losses in challenging states if it finds a complete sequence.
- Independent randomized solver legality tests, exhaustive feasibility oracle and unchanged vision regression tests.
- Long-run benchmark with alternate seed offsets and four **hypothetical** tray generators: uniform, large-piece stress, rejection of entirely unplaceable draws, and hard-piece fair draws.
- A/B sweeps for different survival strengths, line-clear rewards and rescue forecast coefficients.
- Paired seed comparison, estimated 95% interval, P10/median/P90 survival, timing, and illegal-move count.

## Current benchmark evidence (not a release claim)

Earlier v1.3 heuristic settings on macOS CI; `v1.1` is the original frozen solver and game generator is *simulated*:

| Scenario | Seeds | v1.1 avg moves | v1.3 avg moves | Avg change |
|---|---:|---:|---:|---:|
| Uniform tray model, cap 1,000 | 100 | 167.32 | 170.65 | +1.99% |
| Large-piece stress, cap 1,000 | 100 | 37.67 | 39.50 | +4.86% |
| Fair new-tray rejection model, cap 1,500 | 40 | 170.05 | 233.63 | +37.39% |
| Harder fair-dealing stress, cap 1,500 | 40 | 42.65 | 33.83 | **−20.69%** |

A different **unseen** uniform 80-seed group produced negative average gains for all explored survival-strength settings. V1.3 has not achieved consistent superiority, and some P10 outcomes are worse than v1.1. Thus, **do not replace your proven BLINK installation** or describe this as ready for 100 million.

Note that compile-time settings have been changed over the experiment. Results apply only to the commit/flags of the corresponding GitHub Actions run, **not** automatically to every later commit.

## No release without gates
1. Legality and independent exact-feasibility tests must pass, with zero illegal placements.
2. Unit and iPhone ARM64 compilation must pass.
3. On **fresh, unoptimized holdout seeds**, new planner must improve aggregate mean, median and 10th-percentile game survival across multiple generators; report paired uncertainty, not only averages.
4. Review worst-case iPhone solve latency, capture behavior and score/vision correctness with real on-device gameplay.
5. Validate **actual** Block Blast score outcomes rather than inferring 100M readiness from the approximate generator. The 100M target cannot be certified without an actual reproducible run.

## Known limitations and research
Third-party Block Blast web clones use different scoring and piece distributions, and are not authoritative for the iOS app; see https://blockblast.co/faq and https://block-blast.gg/how-to-play . No officially verified 100M benchmark is known here. No in-game memory manipulation, auto-placing, unseen-piece access, or bypass is performed by this solver.

## CI
- `.github/workflows/survival-lab.yml` compiles and tests the experiment, benchmarks four distributions, and uploads reproducible logs.
- `.github/workflows/tune-survival.yml` tests heuristic weights on a separate seed group.
- Experimental dylibs are internal builds; passing ARM64 compilation alone does not make a version safe or 100M-ready.
