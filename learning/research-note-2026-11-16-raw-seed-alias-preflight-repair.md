# Research methodology repair: cross-generator raw RNG start alias detection

Date: November 16, 2026 UTC. Research branch ONLY. This is a **seed-independence/preflight correctness repair**, **not** a new gameplay/training performance gain and **not** a 10x claim.

## Problem confirmed in source

The simulator's unchanged historical seed function in `learning/train_tenx.c` is `(uint32_t)(163000000 + 20000000*scenario + 1000000*epoch + 13717*game)`. Therefore a raw starting PRNG state at `(E, shifted-heavy, game k)` equals the normal state at `(E+40, normal, game k)`; similarly heavy at `E` equals normal at `E+20`. **Different generators redraw shapes differently, so this is NOT identical gameplay**, but it undermines claims that mere *different epoch IDs* guarantee independent raw random starting states across all historical scenario/epoch pairs. The prior ledger had no way to flag that.

## Research-only fix without changing historical seeds

Created `learning/audit_raw_seed_aliases.py` in commit `beecc0738872729a0fb194f692261a2e15fba6c4`. It reads the exact cross-role seed ledger and the source formula, fails closed if the formula changes, and conservatively checks the raw 32-bit start state for every selected train/holdout epoch × all 3 generators × games 0..29 and 100..107 against **all previously documented epoch IDs** in every scenario/offset. This is intentionally conservative because the ledger does not record which exact roles/scenarios/offsets each historical epoch used. It neither changes the simulator RNG nor reserves provisional epochs. With the 90 numeric reservations after iteration 44, there are 180 otherwise-unused 17..2000 epoch IDs rejected by this conservative alias screen and 1714 alias-free candidate IDs. In particular, naive continued high holdout IDs 1975 onward collide with earlier epoch/scenario starting states even though their numeric IDs are new.

Integrated the script into the exact existing reproducible runner `learning/run_tenx_reproducible.sh` **after** the existing distinct-ID/ledger checks, **before** any successful `TENX_PREFLIGHT_ONLY` report and before the compile/training stage. Research commits `ab5a15fb335abcada0ca5d24dfbe47dbf1b82fc4` and `fc1c6752ff793faef64f037a9a3e14e17b134036`. Original 10×/p10/score/combo/legality/censoring gates unchanged. A raw alias is now reported with its concrete proposed and historical epoch/scenario/game combinations. Historical failed runs/artifacts remain untouched.
